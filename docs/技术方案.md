# PersonalKGHub 技术方案

> 更新日期：2026-09-21（对应 M1~M3 完成态 + 排序方案 v2 + 点击埋点第一阶段 + 前端改版：双 tab/首页/可收侧栏）

## 1. 项目定位

运行在本机（Windows 11）的个人知识门户：采集全盘**知识型文件**（pdf/docx/xlsx/pptx/md/txt）的元数据与正文，提供 关键词全文检索、目录树浏览、时间线、文件预览。单机单用户，数据全部落 D 盘。

**不做的事**（明确排除）：照片/代码/微信聊天记录等非知识文件；语义向量检索（2026-09-21 用户决策取消，若日后效果需要再重启）；OCR（MVP 只打 `scanned` 标记）。

## 2. 系统架构：三个常驻部分

```
┌────────────────────┐   TCP 47610    ┌──────────────────────┐
│ 采集器 collector    │ ──JSON lines──▶│ 后端 server (uvicorn) │
│ collector/          │                │ server/               │
│ 需管理员权限          │                │ 127.0.0.1:47600       │
│ 计划任务 ONLOGON     │                │ ①FastAPI ②提取worker  │
│ RL HIGHEST 自启      │                │   ③采集器接收线程       │
└────────────────────┘                └──────────┬───────────┘
                                                 │ HTTP /api
                                      ┌──────────▼───────────┐
                                      │ 前端 web (Vite+React) │
                                      │ localhost:5173 → 代理  │
                                      └──────────────────────┘
```

| 部分 | 启动方式 | 日志 |
|------|----------|------|
| 采集器 | 计划任务 `PersonalKGHub-Collector`（登录自启，`.venv` pythonw + `collector/collector.py`） | `D:\PersonalKGHub\collector_log.txt` |
| 后端 + 前端静态托管 | `python -m uvicorn server.main:app --host 127.0.0.1 --port 47600`（分离进程，同时吐 `web/dist`） | `D:\PersonalKGHub\server_out.log` / `server_err.log` |

**前端为静态托管（2026-09-22 起）**：门户地址 = `http://127.0.0.1:47600`，无 Vite/node 进程。改 `web/src/` 后需 `npm run build`（~2s）再刷新；临时调试可 `npm run dev`（5173 代理到 47600）。

权限要点：MFT/USN 卷句柄必须提权，故采集器独立为提权进程，经本机 TCP 喂数据给普通权限后端。开发 shell 非管理员；重建计划任务需管理员会话（`collector/install_task.ps1`）。

### 2.1 会话模型（2026-09-22 起：桌面快捷方式「KGHub 知识门户」）

**点击 → 起 3 个服务 + 开浏览器；页面关闭 2~3 分钟后 → 服务全部自动停止。**

- `scripts/session_start.vbs` + `session_start.py`（2026-09-22 二版）：快捷方式 → wscript + VBS → `ShellExecute "runas"` 以管理员拉起 **pythonw**（无控制台，零闪屏；ps1 版会闪两次 PowerShell 窗口，已弃）。VBS 带 On Error 自诊断（失败写 session_log）。`session_start.py` 全程 `CREATE_NO_WINDOW`：起后端 → `schtasks /Change /ENABLE`+`/Run` 拉起采集器（任务平时 DISABLED，避免登录自启；**schtasks 没有 /Enable 选项**，无效命令配 Out-Null 会被静默吞掉——曾导致采集器从未拉起而门户显示"未运行"）→ 起看门狗 → 经 **explorer.exe 转交**打开浏览器（提权上下文里直接开 URL，页面 JS 会渲染异常——实锤过的坑）。停止/看门狗清理时必须同时 `/Change /DISABLE`：任务带 ONLOGON 触发器，不禁用会在下次登录自启。
- **心跳抗节流（2026-09-22）**：普通页面定时器会被浏览器按可见性节流（后台标签 5 分钟后 1/分钟，极端 1/小时），人离开 >2.5 分钟心跳断、看门狗误杀——已改为 **Web Worker 心跳**（`/api/ping` POST，专用 Worker 定时器不受节流，人离开多久都不断）。
- **心跳判活**：前端每 10s 轮询 `/api/stats`，后端记 `_web_seen`；`/api/session` 只读返回 `web_idle`（不可写，否则看门狗自己的轮询会污染心跳）。
- `scripts/session_watchdog.py`（pythonw，端口锁 47699 防重）：每 45s 查一次 `web_idle`，>150s 判定界面关闭 → `schtasks /End` 停采集器 + 杀后端进程树 + 自杀。后端刚重启时 `/api/session` 返回 `null`（不误杀）；检查间隔超阈值 = 系统睡过 → 跳过判定（防睡眠唤醒误杀）；启动 180s 内页面从未活跃 → 清理退出。
- `scripts/session_stop.ps1`：手动全停（自提权；pythonw 是本项目独占可全杀，后端按 uvicorn 命令行精确匹配）。
- 取舍：门户关闭期间的文件变动不实时，重开会做一次全量重扫（~40s）+ 补提取，之后自动齐。

## 3. 数据模型（SQLite 单文件，WAL 模式）

库：`D:\PersonalKGHub\data\kghub.db`（当前 ~896MB）。**身份主键 = (volume, frn)**——NTFS 文件引用号，重命名/移动不变，USN 增量更新的锚点。API 层 `pk = "C:12345"` 字符串化。

| 表 | 键 | 用途 |
|----|----|------|
| `dirs` | (volume, frn) | 两卷全部目录骨架（~28 万行，扫描期 USN 事件拼路径需要祖先链）；`kept` 剪枝标记 |
| `files` | (volume, frn) | 圈内知识文件；冗余存 `path`（写入时沿祖先链拼出）；`status`: pending/extracted/failed/cloud |
| `contents` | file_pk | zlib 压缩正文（"燃料"：预览/摘要/标签用，单篇截断 100 万字符） |
| `fts` | FTS5 虚表 | trigram 分词，**contentless_delete 模式**（只存倒排索引不存原文，省 ~1GB；须 SQLite ≥ 3.43） |
| `fts_map` | file_pk → rid | FTS rowid 映射。file_pk 在 FTS 里 UNINDEXED，直接按它删除=全表扫描（曾把系统卡死），删除必须走 rowid |
| `tags` | (file_pk, tag) | jieba 自动标签，top 8/篇 |
| `clicks` | id | 点击行为原始日志（推荐排序的信号源，见 §6.6）。**只追加、不聚合、不删** |
| `scan_seen` | (volume, frn) | 全量重扫的"在场名单"，scan_end 对账清幽灵用（见 §4.4） |

无外键、路径冗余——刻意的松耦合：USN 事件乱序到达时各自独立成立，一致性由周期性全量重扫 + 对账兜底。

## 4. 采集管线

### 4.1 范围圈定（路径为主、扩展名为辅，2026-09-20 拍板）

- `SCOPE_ROOTS`（server/config.py）：C 盘只收 `Desktop` / `Documents` / `Downloads` / `xwechat_files`（微信 4.x；微信 3.x、企业微信、腾讯会议的文件区都在 Documents 下自动覆盖）；**D 盘全盘**。前缀匹配不区分大小写、按目录边界对齐。
- `SCOPE_EXCLUDES`：圈内排除前缀。应用缓存目录藏在圈内路径下（如企微内嵌浏览器的 `Documents\WXWork\qtCef`，其缓存文件不断删建、FRN 反复换代），发现即加进此清单。注意不能按 `Cache` 目录名一刀切——`WXWork\<id>\Cache\File` 是企微收文件的正规存放处。
- 扩展名白名单 `DOC_EXTS` 第二道过滤；`SKIP_DIR_NAMES`（node_modules/.git 等）任意路径段命中即拒；md/txt 在应用目录（appdata/miniconda3）下不收。
- 原则：**文件名/标签排序再好，也救不回没进圈的文件**——圈定是漏杀风险最低的一层。

### 4.2 MFT 全量枚举（collector/mft_scan.py）

`FSCTL_ENUM_USN_DATA` 遍历整卷 MFT，按扩展名过滤，28.7 万条记录 ~40 秒。要点：
- 卷根目录（记录 5）不在 ENUM 输出里，须显式补一条（frn 用 `os.stat('X:\\').st_ino`），否则增量事件拼路径断链
- **HighUsn 必须放开到 signed 最大值**（`1<<63 - 1`），不能用 QUERY 的 NextUsn：USN 日志被外部删除重建/截断后，NextUsn 回到低位，此前改动过的文件记录 USN 高于新 NextUsn，会被 ENUM 整体过滤——文件"隐身"，还被 scan_end 对账误清（2026-09-21 实锤案例：微信发的 PPT 三次全扫都收不到）。对质工具：`fsutil usn readdata <文件>` 看记录 USN vs `fsutil usn queryjournal C:` 看 NextUsn。0/-1 是特殊值（返回空集）
- ERROR_HANDLE_EOF(38) 是正常结束信号

### 4.3 USN 增量监听（collector/usn_watch.py）

`FSCTL_READ_USN_JOURNAL` 阻塞读，两个卷各一线程。事件映射：创建/改名新端/内容变化+CLOSE → upsert；删除 → delete。上下线语义：断线窗口内的事件**丢弃**，靠重连全量重扫自愈（本机场景可接受）。

### 4.4 入库与对账（server/main.py, ingest.py）

- `upsert_file`：拼路径 → 范围/黑名单闸门（`_rejected`）→ os.stat 补全 size/mtime（MFT 无文件大小；纯元数据操作不触发 OneDrive 下载）→ 写库。mtime+size 未变则保留原 status，避免重扫触发全量重提取
- **scan_seen 对账**（2026-09-21）：扫描期间记录在场名单，`scan_end` 时清除"mtime 早于扫描开始 且 不在名单"的文件行及孤儿正文/FTS。背景：Excel/WPS 保存=删旧建新，FRN 换代后旧行成幽灵；删除事件撞上断线窗口丢失后，幽灵只增不减（曾同路径攒 35 行）。对账后重复组归零
- 批量入库先目录后文件，减少扫描期路径断链

## 5. 提取管线（server/extract.py）

后台线程持续消费 `status='pending'`：

```
pending → 属性检查 → cloud（OneDrive 占位不下载）
                   → EXTRACTORS[ext] → 截断 1M 字符 → contents(zlib) + fts 索引 + jieba 标签 → extracted
                   → 失败 → failed
```

- 抽取器：pdf(fitz)、docx/python-docx、pptx/python-pptx、xlsx(openpyxl)、md/txt(编码尝试 utf-8→gb18030→utf-16→replace 兜底)
- 容错：WPS 坏包（rels 指向 NULL）用 zip 直接抠 `<w:t>`/`<a:t>` 文本节点兜底（`_ooxml_text_fallback`）；pptx 备注页判空
- **台账类 xlsx 陷阱**：openpyxl 能解出 GB 级单元格文本，出口统一截断
- 旧版 .doc/.xls/.ppt（~468 个）MVP 不支持，标 failed
- 标签（server/tags.py，提取与回填共用，2026-09-21 重做）：jieba TF-IDF + **本地语料 IDF**（tools/build_idf.py 从全部正文统计 df，ln(N/df)，替换内置新闻语料词典）+ 词性白名单（名词类/英文）+ 噪声规则（哈希串/纯数字/纯符号/通用停用词/纯小写短英文列名缩写）。top 8/篇，正文取前 5 万字符

## 6. 检索（server/api.py，排序方案 v2，2026-09-21 定稿）

### 6.1 召回（两路合并）

1. **FTS MATCH**（trigram，覆盖正文+路径名）：按 bm25（path_name 列 10 倍权重）排序取 **top 200** 作为内容命中候选——bm25 在此只做召回裁剪，不再主导用户可见排序
2. **全库文件名/标签扫描**：对 `status='extracted'` 的 ~5.8k 文件逐个算相似度（纯内存集合运算，毫秒级）

两路都过相同的过滤条件（状态/类型/目录/时间），缺一不可。

### 6.2 排序公式

```
词集：jieba.lcut_for_search（长词+子词都出，防两边分词粒度不一致漏配），丢单字 token，记忆化
sim   = 0.55 × Jaccard(查询词集, 文件名词集)
      + 0.45 × max(Jaccard(查询, 各标签词集))        # sim ∈ [0,1]，权重和为 1
final = sim + 0.5 × bm25n × (1 − sim)              # 衰减融合：已覆盖的相关度不再重复计分
bm25n = FTS 召回排名百分位 (200−rank)/200            # 原始 bm25 无界、跨查询不可比，不可直接加权
排序 = final 降序 → mtime 降序
```

设计意图：文件名/标签相似度为主导信号（文件名恒压标签），bm25 拾遗（标签没覆盖到的内容命中），编辑时间做最终并列裁决。

### 6.3 摘要与短查询

- FTS 是 contentless（无原文），摘要高亮由 `_snippet` 对**最终 N 行**现场解压 contents 截取，Python 侧打 `[[ ]]` 标记
- <3 字符查询走 `files` 表 LIKE（1.8MB，毫秒级），按 mtime 排序
- 查询结果 60 秒缓存（防抖重复请求 + 高频词召回成本吸收）

### 6.4 命中来源字段（2026-09-21 增补）

每张卡片回 `hit_name` / `hit_tags` / `hit_fts`（布尔），前端据此标「文件名命中／标签命中／正文命中／路径命中」。**这同时是排序的调试视图**：调权调错时，界面上能立刻看出是文件名匹配错了还是标签拖了后腿——在那之前排序是黑盒，没法证伪。

| 字段 | 语义 | 对应公式项 |
|------|------|-----------|
| `hit_name` | 查询词集 ∩ 文件名词集 ≠ ∅ | `0.55 × Jaccard` |
| `hit_tags` | 与**任一**标签词集相交 | `0.45 × max Jaccard` |
| `hit_fts` | 进了 FTS 召回 top200 | `bm25n` 那一项 |

`hit_fts` 覆盖 `path_name + content` 两列，所以「正文命中」另由 `snippet` 非空判定（`_snippet` 现场解压真查到词才生成摘要）；`hit_fts && !snippet` = 命中的是路径。短查询（<3 字，走 LIKE）没有 bm25：`hit_name` = 词在文件名里，`hit_fts` = 词只在路径里。**不变量：≥3 字查询下每张卡片至少有一个字段为真**（入选条件就是 sim>0 或进了召回）。卡片还回 `score`（保留 3 位），前端 hover 才显示——平时不打扰，调参时看得见。

### 6.5 实测性能（6213→5796 文档规模）

| 场景 | 延迟 |
|------|------|
| 普通词 / 冷门词 | 43~354 ms |
| 高频词冷查（如"知识图谱"，千级候选） | ~1.9 s（FTS 全候选 bm25 排序，固有成本） |
| 同查询重复（60s 内） | ~2 ms |
| 服务端常驻内存 | ~150 MB（SQLite 按页加载，库不驻留内存） |

### 6.6 点击信号（分两阶段，**当前只做第一阶段**）

用户 2026-09-21 拍板：把"最近一个月点过哪些文件"纳入排序。分两步走，**先攒数据、再调权**——点击数据无法回溯，权重调错了没有历史可重算，所以第一阶段绝不参与排序。

**第一阶段（已完成，2026-09-21）：只记录**

- 表 `clicks(id, path_key, file_pk, kind, q, ts)`，带 `idx_clicks_path_ts`。**只追加原始事件，永不聚合、永不删**——权重/衰减/时间窗全在读取时算，事后才能调参重算（聚合了就等于把历史锁死）。
- `path_key` = **归一化小写路径**，而非 pk：FRN 在 Excel/WPS 保存时会换代（删旧建新），用 pk 记账会让"编辑一次就丢历史"。pk 只作为点击当时的快照存着，供展示/调试用。
- `kind` 五种动作分权重（`api.KIND_WEIGHTS`）：`open` 1.0 > `detail` 0.5 > `locate`/`tree`/`timeline` 0.3。权重写在代码里、不进表——改常量就能重算全部历史。
- **去重**（`CLICK_DEDUPE` = 30 分钟）：同一文件 30 分钟内只留一条，且保留其中权重最高的动作。先点卡片看详情、再点"打开文件" → **升级**成 open，而不是记两条。三种返回 `inserted` / `deduped` / `upgraded`。
- `q` = 产生本次点击的查询词，为将来的"同查询点击"（query-aware）信号留的；从目录树/时间线进去的 q 为空。
- 埋点即发即忘（前端 `recordClick` 吞掉异常），**任何失败只返回 `ok=False`，绝不抛异常**——埋点不该影响正常使用。`/api/stats` 出 `clicks_total` / `clicks_30d` 供观察。

**第二阶段（未做，等 1~2 周数据攒够再动）**

- 公式（讨论稿）：`rel = sim + 0.5×bm25n×(1−rel)` 照旧，再 `final = rel + 0.30×cq×(1−rel) + 0.02×cg`。同样走**衰减融合**：已被相似度覆盖的相关度不再重复加分。
- `cq` = 同查询点击（该 q 下点过此文件），`cg` = 全局点击；计数用**饱和归一化** `c/(c+k)`（k≈3）压住高频文件的霸榜，配**指数时间衰减**（半衰期 7~14 天）。
- 实现照抄 `_sim_index` 的惰性加载 + TTL 缓存套路，写成 `_click_index()`；`/api/search` 顺带吐 `score_parts` 便于观察调参。
- 注意**过滤气泡**风险：点击信号会让"点过的"越排越前，需要靠衰减 + 上限（如 cq 权重不超过 0.3）约束。

## 7. 前端（web/，Vite + React）

设计参照 = 仓库根的 `【参考】知识门户前端设计规格_v1.0.md` 与 `【参考】知识门户样式模板_v1.1.html`（静态 mockup）。**两份都不能照抄**：v1.0 规格的 `match_type: semantic`、`/api/facets`、`/api/index/status`、`/api/events`(SSE) 在本项目都不存在（语义检索已取消）；v1.1 模板的"语义 92%"徽章同理。可搬的是布局骨架、设计 token、键盘交互、竞态处理，以及边界用例清单；**字段与接口一律以本文档 §6 为准**。

### 7.0 样式模板 v1.1 的借鉴与取舍（2026-09-22，用户拍板）

**采纳**：① 配色纪律——黑白灰承担一切强调（`--accent` 从蓝改墨黑 `#1b2533`，深色主题换浅灰），彩色只用于文件类型编码（cat-* 色点），蓝降级为链接色（`--link`）；② 时间快筛已在侧栏；③ 预览栏「命中位置」hit-card：`/api/preview/{pk}?q=` 回 `match_count` + 最多 3 条上下文（`_find_contexts`，[[ ]] 标记），带查询词点开结果时显示；④ `Ctrl+K` 已有；⑤ 响应式断点已有。
**用户明确要求**：① 搜索页**无查询 = 无结果列表**（空态只有搜索框 + chips + 提示，不发请求）；② 时间线只显示年月 + 数量，去掉条形图（侧栏 month-item 与 TimelineView）；③ 侧栏可收起且状态记 localStorage（SSR 测试无 localStorage，须 try/catch 封装——`lsGet/lsSet`）。

### 7.1 第一步改造（2026-09-21 完成）：骨架 + token + 状态层 + 键盘

### 7.2 第二步改造（2026-09-21 完成）：命中来源 + 采集器状态 + 目录筛选 + URL 化

1. **命中来源可视化**：卡片标「文件名命中／标签命中／正文命中／路径命中」+ 排序分（hover 才显示）。字段与不变量见 §6.4——这同时是**排序的调试视图**，出问题时能看出是文件名匹配错了还是标签拖了后腿，调权才有依据。旧版只标了能确定的一条「正文命中」（`snippet` 非空）。
2. **采集器状态上 pill**：`/api/stats` 回 `collector_connected` + `collector_last_seen`。服务端在 `api.collector_state` 维护这两个值：采集器连上 `+1`、断开 `finally` 里 `-1`；收到任何字节（含 30s 一次的空行心跳）就刷新 `last_seen`，90 秒没动静判失联。前端四态优先级：**连不上（红）> 采集器掉线（黄，hover 有排查提示）> 正在提取 > 正常**。2026-09-21 采集器静默死了 3 小时界面毫无痕迹——这一态就是为了不再靠 `netstat` 查。判定用 `=== false` 而非 falsy：后端还没重启时字段缺失是「不知道」，不能冤枉采集器掉线。
3. **目录筛选打通**：`/api/tree` 的 children 现在带 `path`（dirs 表没有 path 列，后端沿 parent_frn 祖先链现场拼，拼接规则与 `ingest._compute_path` 一致，否则前缀对不上）。目录页每个文件夹有「只搜这里」→ 写入 `dir` 状态 → 走搜索现有的 `dir_` 前缀过滤，不加新接口。生效中的目录以 chip 显示在中栏表头和左栏，点掉即恢复全库。类型筛选的计数仍要等 `/api/facets`。
4. **URL 化状态**：hash 路由（`#/q=…&ext=…&time=…&dir=…&mode=…`），刷新不丢查询、可存书签、后退可用。要点：
   - 写入用 `q` 的**防抖值**——每敲一个字都 push 一条历史，后退键就废了
   - 首屏那次用 `replaceState`（别为初始状态多留一条），之后才 `pushState`
   - 监听 `popstate` 而非 `hashchange`（pushState 不触发后者）
   - 只存「导航身份」（模式+查询+三筛选），**不含详情选中项**——搜索成功自动选中第 0 条是规格定的行为，从 URL 还原任意 pk 会跟它打架
   - `ext` 在 URL 边界归一成不带点的小写（TYPE_OPTIONS 的键），否则手写 URL 的 `.docx` 高亮不上筛选
   - 畸形 hash（`#/%`、`#/q` 等）已验证不炸

**前端回归测试**：`web/tests/ui.mjs`（`npm test`，web/ 下）。SSR 渲染真实组件验「给定 URL 的首屏」+ pill/hash 纯函数单测；不引入 jest/vitest，esbuild 随 Vite 一起装。注意打包必须 `--format=esm`：CJS 会把默认导出裹成 interop 对象，React 报 "Element type is invalid"。

## 8. 运维手册

- **一次性脚本**（server/tools/）：`scope_migrate.py`（范围圈定迁移）、`fts_contentless_migrate.py`（FTS 重建）、`dedupe_stat.py`（按磁盘真身去重）、`backfill_tags.py`（存量标签回填）
- **诊断**：`py-spy dump --pid <pid>`（.venv 已装）看卡死线程栈——本系列所有卡点都靠它实锤
- **采集器静默死（2026-09-21 已修）**：`ensure_connected()` 心跳触发的重扫原先裸调 `full_scan(connect_server())`，服务端一重启就抛 `ConnectionResetError` 一路冒到 `main` 外、直接结束采集器进程。曾两次静默停摆（09-20 23:28→09-21 10:37 停了 11 小时；09-21 14:14→16:34 停了 2h20m），`collector_log.txt` 里只有一行 `CRITICAL unhandled` 加调用栈，没人会注意到。已抽成 `rescan_after_disconnect()` 并 `except OSError` 兜住。另：探活原用 `sendall(b"")`，那是空操作、不碰 socket、探不出死连接，已改成真写 `b"\n"`（服务端有 `if not line.strip(): continue`，安全）。**教训：跨进程的"心跳"必须真发字节。**
- **改 `server/` 或 `collector/` 的代码必须重启对应进程才生效**（后端不带 `--reload`，前端 Vite 有 HMR），且**非管理员 shell 杀不掉提权进程**——用自提权脚本（会弹 UAC）：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\restart_backend.ps1` / `scripts\restart_collector.ps1`。铁律：改完不重启 = 用户看到的仍是旧行为。
- **已知坑清单**：Git Bash 传 `$_` 给 PowerShell 会被转义破坏（复杂脚本写 .ps1）；robocopy 统计须加不存在的目标目录 + `/L`；pip 走阿里云镜像但包文件 CDN 晚间可能超时（可 curl 直接拉包文件）；`format.js` 的 `catOf` 返回英文名（doc/pdf…）用于**类名**，而 CSS 变量是 `--cat-1..6` **数字命名**——内联样式拼 `var(--cat-pdf)` 是未定义变量、整条样式静默失效（2026-09-22 首页条形图彩色填充从未渲染过），必须走 `catVar()` 映射；本机 `powercfg /change` 改睡眠超时不生效，要用 `powercfg /setacvalueindex SCHEME_CURRENT SUB_SLEEP STANDBYIDLE <秒> && powercfg /setactive SCHEME_CURRENT`；**schtasks 启用/禁用任务是 `/Change /TN x /ENABLE|/DISABLE`，没有 `/Enable` 选项**（无效命令 + Out-Null 会静默吞错，脚本里务必检查 `$LASTEXITCODE`）
- **性能陷阱备忘**：FTS 按非索引列删除=全表扫描；`volume||frn=?` 无索引要用复合主键；全量重扫必须对账否则幽灵行堆积；**dirs 写入禁用 `INSERT OR REPLACE`**——它会把 `kept` 冲回默认 0，而扫描中途断连时残留 batch 走到循环外的 `_apply_records`，`scan_end` 的 `tree.rebuild` 永不执行，`kept` 就永久脏掉（曾把 C:\ 根冲成 0，整棵 C 盘树从门户消失）。已改为 `ON CONFLICT DO UPDATE`，只更新 parent_frn/name
